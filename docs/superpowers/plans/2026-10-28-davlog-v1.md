# davlog v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single-binary Rust WebDAV server that serves a git working tree, turns every client write into a git commit, optionally pushes to a write-only backup remote, and alerts the operator by email (via a pluggable trait) when anything goes wrong.

**Architecture:** One tokio process. `hyper` serves HTTP and delegates WebDAV to the `dav-server` crate through our own `DavFileSystem` (`GitFs`) that hides `.git`, writes atomically via temp files inside `.git`, enforces the size limit, and reports each mutation to a `Committer`. The `Committer` is one actor with three timing policies (per_request default, debounce, interval) that stages only the changed paths. All libgit2 calls go through one mutex-guarded `Repo` and run under `spawn_blocking`. A `Pusher` loop pushes on a timer and, on a rejected push, pauses and alerts. It never rebases or merges.

**Tech Stack:** Rust (cargo 1.91.1), tokio, hyper 1 + hyper-util, dav-server 0.11, git2 0.21, serde + toml, lettre 0.11, tracing, anyhow/thiserror, argon2, tempfile + reqwest (dev).

**Spec:** `docs/DESIGN.md` (approved 2026-10-28), `docs/CONCERNS.md`, `docs/OPEN-QUESTIONS.md`.

## Global Constraints

- Language Rust. Git access only through `git2`. **Never shell out to the `git` binary** in product code or in Rust tests (build fixtures with `git2`). Only `scripts/smoke.sh` may call the `git` CLI, to inspect results.
- The project name `davlog` appears only in: `Cargo.toml` package name, `src/brand.rs` constants, `README.md`/docs. Everything else (user-agent, config path, env prefix, commit author default, message template default, ref names) derives from `brand.rs`.
- One repo, one basic-auth user per instance. Do not assume any specific WebDAV client.
- Never force-push. Never rebase, merge, or fast-forward the working tree. Never touch rebase/merge state or a foreign `index.lock` in `.git`.
- Clients can never read or modify `.git`: 404 on every method for any path component equal to `.git`, and refuse it as a MOVE/COPY destination.
- Default commit mode `per_request`, `wait_for_commit = true`. Fallback default `debounce` only if Task 4 shows `per_request` is too slow.
- `max_file_size` default `100MiB`; `0` means unlimited; over the limit gives 413 and removes the temp file; a chunked upload with no `Content-Length` is cut off mid-stream.
- Alerts never block serving, committing or pushing; a notifier is never called while the repo mutex is held. SMTP has a timeout.
- All git behaviour is set in the app config, never by the host. The process ignores the system, global, XDG and program-data git config (set their libgit2 search paths to empty before any repo is opened), and the optional `[git.config]` table in the app config is written to the repo-local config at every startup. Keys under `remote.*`, plus `core.bare` and `core.worktree`, are rejected (remote settings live in `[push]`; the others would break the server).
- Push is optional: no `[push]` section or `enabled = false` means no pusher, no remote, no push alerts.
- Mutating methods (PUT, DELETE, MKCOL, MOVE, COPY, PROPPATCH, LOCK) return `503` with `Retry-After` while a human has rebase/merge state or a foreign `index.lock` in `.git`; reads (GET, HEAD, PROPFIND, OPTIONS) continue.
- Logs go to stdout/stderr only (tracing). Secrets (password, SSH key, SMTP password, token) come from files or `DAVLOG_*` env vars and never appear in logs or `Debug` output.
- Empty directories exist on disk only; no `.gitkeep` and no `track_empty_dirs` setting in v1 (YAGNI; builder's call per the design).
- Commit messages in this repo are normal prose and end with the attribution line given by the harness.

## Review Focus

Failure modes the spec implies but no spec section tests. Each has a named test in the task that owns the code.

1. Percent-encoded invalid UTF-8 in a path, plus spaces, `#`, `%` and non-ASCII names: valid names round-trip and commit; invalid UTF-8 gets 400, never a panic (Task 6).
2. Client disconnects mid-upload: the temp file is removed, nothing is committed, the tree is unchanged (Task 6).
3. PUT of identical content, and a zero-byte PUT: 2xx and no empty commit; a zero-byte file still commits once on first create (Tasks 3, 6).
4. A client-written `.gitignore` that matches its own files: 2xx, files stay on disk, nothing for them is committed, and a warning is logged (Task 3).
5. Request-shape tricks: MOVE/COPY onto itself, `Destination` pointing into `.git`, encoded `..`, directory over file and file over directory: correct 4xx and no repo damage (Task 6).

### Task 6: GitFs (the WebDAV filesystem)

**Files:**
- Create: `src/davfs.rs`
- Modify: `src/lib.rs`
- Test: `tests/davfs.rs`

**Interfaces:**
- Consumes: `Committer::record`, `LimitsConfig`, `brand::TMP_DIR_NAME`, dav-server's `DavFileSystem`, `DavFile`, `DavMetaData`, `DavDirEntry`, `DavPath`, `FsError`, `OpenOptions`.
- Produces: `pub struct GitFs`; `pub fn GitFs::new(root: PathBuf, max_file_size: Option<u64>, committer: Committer) -> Box<GitFs>` (dav-server wants a boxed filesystem; match its builder's expected type). Methods implemented: `open`, `read_dir`, `metadata`, `symlink_metadata`, `create_dir`, `remove_dir`, `remove_file`, `rename`, `copy`.

Behaviour, all enforced inside `GitFs`:
- **Path mapping:** `DavPath` to repo-relative path. Any component equal to `.git` (exact match) gives `FsError::NotFound` on every method and `FsError::Forbidden` for create/write/rename/copy targets. Invalid UTF-8 gives `FsError::GeneralFailure`-class error that maps to 400 (verify the status in the test; if dav-server maps it differently, reject earlier in `server.rs` Task 7 and keep the test there). Any resolved path that escapes `root` is rejected; symlinks are never followed (`symlink_metadata` everywhere) and a symlink entry is reported as `NotFound`.
- **Atomic writes:** `open` with `write`/`create` creates a temp file `root/.git/<TMP_DIR_NAME>/<uuid>` (same filesystem, never tracked). The returned `DavFile` counts bytes in `write_buf`/`write_bytes`; exceeding `max_file_size` returns `FsError::TooLarge` and deletes the temp file. `flush` fsyncs, renames over the target, and calls `committer.record(Change{op: Put, ..})`. Dropping the `DavFile` without a successful flush deletes the temp file. On startup `GitFs::new` removes leftover temp files.
- `create_dir` records `Mkcol` and does not fail on a path that already exists as a directory (dav-server returns 405 itself). `remove_file`/`remove_dir` record `Delete`; `rename` records `Move{path,to}`; `copy` records `Copy{path: source, to: Some(dest)}`. Record after the filesystem operation succeeds.
- **Metadata:** `len`, `modified`, `is_dir`, `etag` = `"{len:x}-{mtime_nanos:x}"`. Directory entries skip `.git` and the temp dir.
